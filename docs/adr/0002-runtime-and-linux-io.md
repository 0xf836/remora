# ADR-0002: Exclusive connection ownership, Linux batching and deadline pacing

**Scope update — 2026-10-17:** [ADR 0024](0024-defer-arm64-release-scope.md) supersedes the original ARM64 commitment below. Linux GNU x86_64 is the sole current required release target; ARM64 is deferred outside completion gates. The original research/decision text remains historical.

Date: 2026-10-10. Revised: 2026-10-11. Status: selected baseline; early MVP measurements guide normal incremental refinement, with no separate feasibility gate.

## Context

Initial Linux x86_64/ARM64 support and 32-session bidirectional goals need bounded buffers, accurate pacing, partial-progress correctness and maintainable integration. One reactor's capacity has not been measured.

## Options considered

| Option | Advantages | Costs / contract concerns |
|--------|------------|---------------------------|
| Tokio current-thread + AsyncFd + direct quiche | Existing lifecycle/readiness tools, explicit ownership/limits/timerfd policy | Own CID routing, timers, pacing and reviewed Linux adapter |
| Plain mio | Direct readiness loop | More custom shutdown/setup/timer coordination; no proven speed advantage |
| tokio-quiche with ready-made H3Driver | Maintained worker, GSO, CID routing, diagnostics and CONNECT-UDP support | Fixed flow channels, unbounded command/event channels, pre-auth flow allocation and pacing-offload assumptions need audit/adaptation |
| tokio-quiche ApplicationOverQuic custom handler | Reuses worker while controlling H3/policy/queues | Worker pacing/path-source behavior still must satisfy Remora contract |
| io_uring multishot/provided buffers | Potential syscall/wakeup reduction | Completion/cancellation/buffer-ring invariants and kernel requirements; no workload evidence |
| Multiple connection-owner shards | Parallel independent connections | CID routing, admission/fairness/accounting complexity; cannot parallelize one quiche connection |

## Decision

One current-thread Tokio reactor with nonblocking AsyncFd sockets initially. State is exclusively owned, with bounded setup auxiliary work and readiness notifications; never an unbounded per-packet queue. recvmmsg/sendmmsg with max batch 32 is baseline; preserve empty datagrams and exact accepted prefixes. Use shared bounded scratch/pool storage and explicit session/connection work quanta. One CLOCK_MONOTONIC timerfd services fine pacing/transport deadlines. Respect SendInfo.from/to/at and retain generated bytes on EAGAIN. No timer-based waiting merely to fill a batch, no busy spin by default.

CUBIC plus enabled pacing is default. Explicit supported BBRv2 comparison, optional probed outer GSO/GRO, separate v4/v6 sockets and pktinfo selection. GSO sends only already due compatible segments; GRO reconstructs original datagrams before quiche. No introduced fragmentation; separate target/outer PMTU handling. Public quiche 0.30 RecvInfo has no ECN input, so initial outer packets use Not-ECT.

Accept offload off/auto without making optional implementation an MVP prerequisite. An unimplemented auto path uses baseline I/O and reports effective off/not_implemented without a probe or kernel/NIC-unavailable claim. An implemented auto path probes capability/eligibility and exports requested/effective state with the fixed reasons from the config/diagnostics contracts. Per-packet incompatibility still uses baseline I/O even when a socket/path's offload is available; preserve pacing, ownership and accepted-prefix rules in either case.

Consider tokio-quiche 0.20.0 plus a custom ApplicationOverQuic handler during normal architectural refinement when API/resource constraints or early MVP profiles justify a comparison; no comparison is required before implementation can begin. Public package supports quiche ^0.30.0. Source comparisons must use the exact package: quiche Git tag 0.30.0 contains tokio-quiche 0.19.1, so it cannot alone prove published 0.20 behavior. Official public source also exposes the H3 channel and worker pacing concerns. Adopt reuse if supported APIs or a small maintainable upstream change meet identical bounds/pacing/isolation. Do not invent a benchmarked advantage for the own reactor.

Before implementing bespoke unsafe ancillary code, assess Cloudflare datagram-socket for truncation, per-message source selection, PMTU errors and batching invariants. Reuse audited compatible parts; otherwise keep the missing syscall functions in one reviewed Linux module. This assessment does not authorize another general I/O backend. Regardless of wrapper selection, the contract and tests are fixed.

## Output lifecycle and capacity risks

### Phase 1 datagram-socket reuse assessment

Inspected Cloudflare's datagram-socket **0.8.0** at quiche tag **0.30.0**,
using the GitHub contents API. Exact source blobs:
`Cargo.toml` f836c8b8d1902892b0036c4b685b97668bcebbc4,
`src/mmsg.rs` 194d935e7f319400224f7837a6b4c8b442094364,
`src/datagram.rs` 1b90619969102e22e38b5da108f83dcf5ceb1468.
This identifies the reviewed source rather than relying on rolling API docs.
Its Tokio dependency uses the same upstream workspace; it does not provide a
different runtime. It is not added as a Remora dependency in Phase 1.

| Required behavior | Observed source behavior | Reuse decision |
|-------------------|--------------------------|----------------|
| Bounded mmsg calls and accepted prefixes | `MAX_MMSG=16`; recreates headers per chunk; returns accumulated successful message count after a later syscall error | Useful batching/readiness pattern; caller still owns prefix accounting, pacing and bounded work. Remora's batch-32 contract needs adaptation. |
| Empty UDP and truncation detection | Returned messages advance `ReadBuf` by `msg_len`, including zero; receive does not inspect `msg_flags` for MSG_TRUNC | Empty messages are represented, but silent truncation cannot satisfy the contract; do not adopt receive unchanged. |
| Remote/local address and source selection | mmsg headers set `msg_name` and `msg_control` to null; batch traits describe connected sockets; single `poll_recv_from` returns remote address only | Insufficient for wildcard outer/client sockets: require per-message sockaddr, pktinfo receive and explicit outgoing source ancillary data. |
| PMTU, GRO and kernel overflow metadata | No ancillary parsing, MSG_CTRUNC validation, error-queue processing or no-fragment policy in the reviewed mmsg API; a zero-progress failure returns OS error, later errors are hidden behind accepted count | Remora must classify EMSGSIZE, configure PMTU, validate metadata and account overflow/optional GRO in its Linux boundary. |
| Readiness and buffer ownership | Poll macros combine Tokio readiness with `try_io`; receive casts uninitialized buffer storage and initializes returned lengths | Reuse the readiness idea, not unreviewed unsafe code. Adapter tests must prove lengths, alignment, initialization and retained suffix ownership. |

Decision: retain one narrow safe-facing Linux adapter in `src/udp.rs` for
recvmsg/sendmsg, mmsg, ancillary metadata and timerfd. Reuse socket2/libc and
Tokio readiness facilities already selected; do not add datagram-socket solely
for connected batching while duplicating the required metadata path. If later
copying/adapting upstream code, preserve its BSD license notices and document
each changed safety invariant. This is a source/API assessment, not an
independent safety audit or performance comparison. T016/T017 must still verify
real syscalls and scripted partial progress before accepting the adapter.

Sources: [tagged manifest](https://github.com/cloudflare/quiche/blob/0.30.0/datagram-socket/Cargo.toml),
[mmsg implementation](https://github.com/cloudflare/quiche/blob/0.30.0/datagram-socket/src/mmsg.rs),
[socket traits](https://github.com/cloudflare/quiche/blob/0.30.0/datagram-socket/src/datagram.rs).

After independent review, generated ciphertext remains immutable and ordered within its original connection across EAGAIN and individual session close, under [ADR-0001's commitment rules](0001-transport-profile.md#transmission-commitment-and-close-independent-review-r1). Do not derive per-session ciphertext cancellation from native DATAGRAM purge. Fair scheduling still rotates independent connections; an earlier future-paced packet cannot be bypassed by later same-connection output. Test partial progress, preserved pacing and the original output deadline.

One packet owner is a capacity hypothesis. The SC-007 two-core process budget includes setup/writer work and does not parallelize that owner. Early x86_64 profiles must report owner-thread CPU/headroom and assess 32-session progress, control-timer servicing and conservative native queue expiry/purge under load. These measurements guide refinement during normal implementation; no separate prototype or dual-architecture checkpoint is introduced.

## Consequences

Baseline works without runtime network-administration privileges or qdisc setup. Timerfd accuracy is measured through lateness/burst histograms; it is not a latency promise. Native syscall/FFI qualification remains necessary for each claimed release target; start x86_64 development/checks first and add ARM64 validation without blocking that work. Default queue/batch values can be revised before release through measured results while preserving SC thresholds. Sharding/io_uring/SO_TXTIME are deferred until a recorded bottleneck and ADR justify them.

Evidence: [Tokio AsyncFd](https://docs.rs/tokio/1.53.2/tokio/io/unix/struct.AsyncFd.html), [timerfd](https://man7.org/linux/man-pages/man2/timerfd_create.2.html), [published tokio-quiche metadata](https://docs.rs/crate/tokio-quiche/0.20.0), [ApplicationOverQuic](https://docs.quic.tech/tokio_quiche/trait.ApplicationOverQuic.html), [official H3 driver source](https://docs.quic.tech/src/tokio_quiche/http3/driver/mod.rs.html), [official worker source](https://docs.quic.tech/src/tokio_quiche/quic/io/worker.rs.html), [tagged package version](https://raw.githubusercontent.com/cloudflare/quiche/0.30.0/tokio-quiche/Cargo.toml).

## Phase 5 measured selection — 2026-10-12

The ten low-rate parameter experiments and five-pair prospective reference are
recorded in `docs/performance.md` before candidate work. CPU is substantial at
5000 packets/s/direction, but short overlapping batch/CC results and sparse CPU
samples do not justify selecting an acceleration or changing default policy.
Retain mmsg32, CUBIC, timerfd and current finite pools/queues. Defer GSO/GRO,
backend/sharding and allocator changes until a separately referenced high-rate
profile identifies a repeatable bottleneck and a candidate preserves all
ownership/pacing/resource/security criteria. This is a measured decision to
retain the baseline, not a performance success claim.

`auto` remains accepted with effective off and fixed reason `not_implemented`;
it performs no capability probe and makes no hardware-unavailable claim. Native
off/auto tests therefore exercise the same datagram I/O path. Without a GRO
splitter, reject every UDP-level ancillary segment marker (known, malformed or
unknown future type) rather than feeding an aggregate to QUIC as one datagram.
No packet grouping or additional mutable ownership is introduced. Existing
scripted owner checks retain future deadlines, mixed ciphertext, EMSGSIZE
failed-front and accepted-prefix invariants. The applicable T055 comparison
uses the already frozen Phase 5 policy and exact retained test-only traffic
executable, despite subsequent test-harness evolution.

The native burst characterization exposed synchronous ENOBUFS (errno 105)
from runner-owned netem queue pressure. Preserve the association: drop only the
unaccepted outer FIFO front, count `outer_send_pressure`, and allow QUIC control
recovery. It is not a PMTU observation or fabricated Session application loss.
Relay ENOBUFS drops the exact application packet with `socket_error` without
closing its Session. EAGAIN continues to retain its original suffix/deadline;
hard errors retain numeric errno in the connection failure record. Adapter
`send_enobufs`/`send_emsgsize` count actual failed native submissions, separately
from PMTU prechecks. Scripted accepted-prefix tests cover both failure classes;
original native failures remain retained before the fix.
