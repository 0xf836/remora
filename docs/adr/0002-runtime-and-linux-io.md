# ADR-0002: Exclusive connection ownership, Linux batching and deadline pacing

Date: 2026-10-10. Revised: 2026-10-11. Status: selected baseline; early MVP measurements guide normal incremental refinement, with no separate feasibility gate.

## Context

Initial Linux x86_64/ARM64 support and 32-session bidirectional goals need bounded buffers, accurate pacing, partial-progress correctness and maintainable integration. One reactor's capacity has not been measured.

## Options considered

| Option | Advantages | Costs / contract concerns |
|--------|------------|---------------------------|
| Tokio current-thread + AsyncFd + direct quiche | Existing lifecycle/readiness tools, explicit ownership/limits/timerfd policy | Own CID routing, timers, pacing and reviewed Linux adapter |
| Plain mio | Direct readiness loop | More custom shutdown/setup/timer coordination; no proven speed advantage |
| tokio-quiche with ready-made H3Driver | Maintained worker, GSO, CID routing, diagnostics and CONNECT-UDP support | Fixed flow channels, unbounded command/event channels, pre-auth flow allocation and pacing-offload assumptions need audit/adaptation |
| tokio-quiche ApplicationOverQuic custom handler | Reuses worker while controlling H3/policy/queues | Worker pacing/path-source behavior still must satisfy Remora contract |
| io_uring multishot/provided buffers | Potential syscall/wakeup reduction | Completion/cancellation/buffer-ring invariants and kernel requirements; no workload evidence |
| Multiple connection-owner shards | Parallel independent connections | CID routing, admission/fairness/accounting complexity; cannot parallelize one quiche connection |

## Decision

One current-thread Tokio reactor with nonblocking AsyncFd sockets initially. State is exclusively owned, with bounded setup auxiliary work and readiness notifications; never an unbounded per-packet queue. recvmmsg/sendmmsg with max batch 32 is baseline; preserve empty datagrams and exact accepted prefixes. Use shared bounded scratch/pool storage and explicit session/connection work quanta. One CLOCK_MONOTONIC timerfd services fine pacing/transport deadlines. Respect SendInfo.from/to/at and retain generated bytes on EAGAIN. No timer-based waiting merely to fill a batch, no busy spin by default.

CUBIC plus enabled pacing is default. Explicit supported BBRv2 comparison, optional probed outer GSO/GRO, separate v4/v6 sockets and pktinfo selection. GSO sends only already due compatible segments; GRO reconstructs original datagrams before quiche. No introduced fragmentation; separate target/outer PMTU handling. Public quiche 0.30 RecvInfo has no ECN input, so initial outer packets use Not-ECT.

Accept offload off/auto without making optional implementation an MVP prerequisite. An unimplemented auto path uses baseline I/O and reports effective off/not_implemented without a probe or kernel/NIC-unavailable claim. An implemented auto path probes capability/eligibility and exports requested/effective state with the fixed reasons from the config/diagnostics contracts. Per-packet incompatibility still uses baseline I/O even when a socket/path's offload is available; preserve pacing, ownership and accepted-prefix rules in either case.

Consider tokio-quiche 0.20.0 plus a custom ApplicationOverQuic handler during normal architectural refinement when API/resource constraints or early MVP profiles justify a comparison; no comparison is required before implementation can begin. Public package supports quiche ^0.30.0. Source comparisons must use the exact package: quiche Git tag 0.30.0 contains tokio-quiche 0.19.1, so it cannot alone prove published 0.20 behavior. Official public source also exposes the H3 channel and worker pacing concerns. Adopt reuse if supported APIs or a small maintainable upstream change meet identical bounds/pacing/isolation. Do not invent a benchmarked advantage for the own reactor.

Before implementing bespoke unsafe ancillary code, assess Cloudflare datagram-socket for truncation, per-message source selection, PMTU errors and batching invariants. Reuse audited compatible parts; otherwise keep the missing syscall functions in one reviewed Linux module. This assessment does not authorize another general I/O backend. Regardless of wrapper selection, the contract and tests are fixed.

## Output lifecycle and capacity risks

After independent review, generated ciphertext remains immutable and ordered within its original connection across EAGAIN and individual session close, under [ADR-0001's commitment rules](0001-transport-profile.md#transmission-commitment-and-close-independent-review-r1). Do not derive per-session ciphertext cancellation from native DATAGRAM purge. Fair scheduling still rotates independent connections; an earlier future-paced packet cannot be bypassed by later same-connection output. Test partial progress, preserved pacing and the original output deadline.

One packet owner is a capacity hypothesis. The SC-007 two-core process budget includes setup/writer work and does not parallelize that owner. Early x86_64 profiles must report owner-thread CPU/headroom and assess 32-session progress, control-timer servicing and conservative native queue expiry/purge under load. These measurements guide refinement during normal implementation; no separate prototype or dual-architecture checkpoint is introduced.

## Consequences

Baseline works without runtime network-administration privileges or qdisc setup. Timerfd accuracy is measured through lateness/burst histograms; it is not a latency promise. Native syscall/FFI qualification remains necessary for each claimed release target; start x86_64 development/checks first and add ARM64 validation without blocking that work. Default queue/batch values can be revised before release through measured results while preserving SC thresholds. Sharding/io_uring/SO_TXTIME are deferred until a recorded bottleneck and ADR justify them.
